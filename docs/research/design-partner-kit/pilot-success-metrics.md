  `d50d0dc2` (Prisma model names, with the SQL table name from `@@map` in brackets).
- **Targets are proposals.** They come from the spec success metrics, which are themselves estimates, or are left blank

**Notes.**

- How conversion works today: `accept()` in `apps/api/src/modules/tasks/prisma.repository.ts` (L263–291) marks the
  draft `converted`, writes a `TaskApproval` with `decision: 'approved'`, and creates the `Task` with the title the
  reviewer submits. It does **not** copy `suggestedAssigneeId`; the assignee is set later through the task update path.
  So M5 compares the final task title with the draft title, and M6 compares the final assignee with the suggestion
  where both exist. Later edits to the task also count as edits (**interpretation**: we can't tell an accept-time edit
  from a later one without an event).
- "Since last meeting" panel opens (spec 02) and grade overrides (spec 01) have no column yet. They need product
  events once those specs ship. Until then, ask about them in the check-in interviews.
- There is no meeting-series field in `Meeting`, so recurring-meeting metrics need `CalendarEventLink` or spec 02.
- Counts must be per org and exclude soft-deleted rows (`deletedAt is null`).
- Collect metrics as counts and ratios only. Don't export meeting content or names for the metrics sheet.

## 2. Baseline capture (proposal)

- **Weeks 1–2 (baseline).** The team uses MeetOps as normal, but we don't change prompts or settings. M3–M9, M14 and
  M16 from these two weeks are the baseline.
- **Before week 1 (manual).** In the kick-off, the champion estimates for one typical recent meeting: minutes spent
  writing up tasks afterwards, and how many tasks were missed or reassigned in the last month. These are self-reported
  and labelled as such.
- **Eval baseline (M15).** Run today's default STT route (AssemblyAI with `language_detection`,
  `packages/ai-core/src/adapters/assemblyai.ts` L63) on the eval set before any routing change.
- **Freeze.** Record the prompt versions (`meeting-summary@1`, `action-items@1`) and STT model in use for the baseline.

## 3. Reporting (proposal)

- A weekly one-page summary per partner with M1–M16, built from counts only.
- A cohort view at weeks 4 and 8.
- Interview findings are tagged to gaps and bets and kept separate from the numbers.
